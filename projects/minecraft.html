Minecraft LLM Agent

Independent text-based agents combining hierarchical planning, personal memory, and chat-based cooperation in Minecraft.

Work: Ongoing

Problem

Real-time play creates a trade-off between response speed, input size, and reasoning quality. A model that carefully considers every action can respond too slowly; sending more world information also makes it harder to find the facts that matter. This project separates slower planning from fast execution and makes context available when a decision needs it.

Layered planning & execution

Goal, task, and conversation LLM calls serve different roles. Slower, higher-level decisions prepare policies for real-time action selection; a fast selector adapts execution to the current situation, and Mineflayer carries out the actions. Generation numbers let the system discard stale asynchronous responses.

Query first, then decide

Tool calls were sometimes omitted inside a large decision prompt. A separate, short query-selection call now chooses map or path queries before goal and task reasoning. Raw tool output is converted into decision-relevant facts rather than passed through as a large observation dump.

These facts include space dimensions, blockage and path-clearing costs, and distances or facilities across known places. Observation timestamps and change indicators help avoid repeating queries when the relevant state is unchanged.

Reflection as situational guidance

Reflection turns actions and outcomes into reusable guidance. Evidence, counterexamples, and the IDs of guidance used in a decision support later revision or removal. Relevant guidance reaches goal reasoning, task reasoning, and the fast action selector—not the conversation layer. Current observations take precedence over remembered advice.

Cooperation without shared memory

Each bot runs in a separate process with personal memory. There is no central coordinator or shared memory: the bots coordinate through in-game chat and actions in the same world. Mentor is an experimenter participating in chat. AI sessions used for development or server management sit outside the agents’ runtime decisions.

Observed progress & open questions

Observed tasks include digging a route to a blocked crafting table and crafting there, comparing known places before moving, and cooperating to build shelters, a base camp, and iron-tier equipment.

These are completed task examples, not a measured success rate. Repeatability, coordination deadlocks, and stability over longer tasks remain evaluation priorities. The system is text-based; vision is not implemented.
